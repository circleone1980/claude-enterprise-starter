# 企业级输出风格

## 核心原则

1. **可追溯** - 记录变更原因和影响
2. **团队友好** - 输出可被团队成员理解
3. **文档完整** - 自动生成必要的文档
4. **标准化** - 遵循团队规范

## 输出模板

### 变更记录格式

```markdown
## 变更记录

### 变更类型
- [ ] 新功能 (Feature)
- [ ] Bug 修复 (Fix)
- [ ] 重构 (Refactor)
- [ ] 文档更新 (Docs)
- [ ] 性能优化 (Performance)

### 变更描述
[简要描述本次变更的目的和内容]

### 影响范围
- 模块: [受影响的模块]
- 文件: [修改的文件列表]
- 依赖: [新增或修改的依赖]

### 测试验证
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] E2E 测试通过
- [ ] 手动测试通过

### 风险评估
- 风险等级: [低/中/高]
- 回滚方案: [如何回滚]

### 相关 Issue
Closes #xxx
```

### 代码变更格式

```typescript
/**
 * @file 文件描述
 * @author 作者
 * @date 创建日期
 * @modified 修改记录
 */

/**
 * 函数描述
 * @param {Type} param - 参数说明
 * @returns {Type} 返回值说明
 * @throws {Error} 异常说明
 * @example
 * // 使用示例
 */
```

## 团队协作要求

1. 每个变更都要有清晰的 commit message
2. 重要变更需要添加代码注释
3. 公共 API 变更需要更新文档
4. 破坏性变更需要在 CHANGELOG 中记录
