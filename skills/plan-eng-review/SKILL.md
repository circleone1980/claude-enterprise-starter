# Plan Eng Review（工程审查）

## 目的

锁定架构、数据流、边界情况和测试矩阵。强制暴露隐藏假设。

## 何时激活

- autoplan 流水线内部调用
- 用户说 "工程审查" / "架构审查"

## 前置条件

- OFFICE_HOURS.md 和 DESIGN.md 已存在

## 工作流程

### Step 1: 架构设计

绘制系统架构：
- ASCII 架构图（组件关系、服务边界）
- 数据流图（数据从哪里来、到哪里去）
- 状态机（核心实体的状态转换）
- 部署架构（服务如何部署）

### Step 2: 隐藏假设暴露

强制回答以下问题：
1. 假设了什么样的网络条件？
2. 假设了什么样的用户设备？
3. 假设了什么样的数据量级？
4. 假设了什么样的并发量？
5. 假设了什么样的安全模型？
6. 假设了什么样的错误发生频率？

### Step 3: 边界情况分析

列出所有可能的边界情况：
- 输入验证边界
- 数据一致性边界
- 并发访问边界
- 网络故障边界
- 认证/授权边界
- 性能边界

### Step 4: 测试矩阵

为每个核心功能定义测试矩阵：

| 功能 | 正常路径 | 边界情况 | 错误路径 | 并发场景 |
|------|---------|---------|---------|----------|

### Step 5: 故障模式分析

分析所有可能的故障模式：
- 单点故障
- 级联故障
- 数据丢失场景
- 部分失败处理

### Step 6: 安全评估

基本安全检查：
- 认证/授权模型
- 数据加密需求
- API 安全（速率限制、输入验证）
- 已知攻击面

### Step 7: 输出

输出工程审查结果：
- 架构图和数据流
- 隐藏假设清单
- 边界情况清单
- 测试矩阵
- 故障模式清单
- 安全建议

## 质量检查清单

- [ ] ASCII 架构图已生成

- [ ] 至少 6 个隐藏假设已暴露
- [ ] 边界情况清单存在
- [ ] 测试矩阵已定义
- [ ] 故障模式已分析
