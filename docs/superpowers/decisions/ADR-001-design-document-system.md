# ADR-001: 设计文档分层体系

> **状态**: Accepted
> **决策日期**: 2026-04-08
> **决策者**: Architect + PM
> **影响范围**: 大型

---

## Context（背景）

在开发企业级项目前，需要产出大量设计文档（PRD、架构设计、API设计等）来指导 Agent Team 自动开发。原模板缺少：
- 文档存放位置和目录结构
- 文档与 Agent 的关联机制
- 文档生命周期管理
- 设计变更处理机制（ADR）

**问题**: Agent 不知道去哪里找设计文档，也不知道何时需要读取，导致开发偏离设计意图。

---

## Decision（决策）

采用"带自动反馈环的分阶段预设计"方案：

1. **文档分层体系**: 冻结层（Phase 1 产出，锁定）、演化层（持续更新）、ADR 层（变更记录）
2. **design-context 技能**: Agent 启动时根据角色自动读取相关设计文档
3. **技能触发规则**: 确保技能在合适的时机被调用
4. **ADR 机制**: 处理设计变更，区分小型（Architect 审批）和大型（人类审批）

---

## Alternatives Considered（备选方案）

### 方案 1: 边开发边设计（敏捷式）
**优点**: 灵活、快速迭代
**缺点**: AI Agent 缺乏全局视野，容易产生设计不一致
**不选择原因**: Agent Team 需要明确的设计文档作为执行依据

### 方案 2: 完全预设计（瀑布式）
**优点**: 设计完整、一致性好
**缺点**: 前期投入大、设计可能有缺陷
**不选择原因**: 过于僵化，无法应对开发中的问题

### 方案 3: 带自动反馈环的预设计（最终选择）
**优点**: 前期设计完整 + ADR 机制处理变更
**缺点**: 需要维护 ADR 流程
**选择原因**: 平衡了设计完整性和灵活性

---

## Consequences（影响）

### Positive（正面影响）
- Agent 有明确的设计文档作为执行依据，减少开发偏离
- ADR 机制提供了设计变更的可审计追踪
- 文档分层清晰，Agent 可按需读取
- 技能触发规则确保技能被正确调用

### Negative（负面影响）
- Phase 1 前期投入增加（需要完成冻结层文档）
- ADR 流程增加了设计变更的成本（但这是有意为之）
